# データ形式

パイプライン（`npm run update`）が `data/` に出力する JSON の形式。アプリはこのファイルだけを読む。

## 取得元

Steam の公式お知らせ（日本語版）:
`https://store.steampowered.com/events/ajaxgetpartnereventspageable/?appid=381210&l=japanese`

タイトルが `10.2.0 | パッチノート` や `PTB 10.2.0 | ...` の形のものだけをパッチとして扱う。
本文は BBCode（`[h2]` `[list]` `[*]` `[p]` `[b]` など）で、変更点は次のように書かれている:

```
[b]14/16/18%[/b]の迅速を得る（変更前：6/12/18%）。
通常攻撃が命中しなかった時のクールダウンが[b]15/20/25%[/b]短くなる（新効果）。
```

太字 = 変更後の値、`（変更前：…）` = 変更前の値、`（新効果）` = 追加された効果。

## ファイル

| パス | 内容 |
|---|---|
| `data/raw/<id>.json` | Steam から取ってきた本文そのまま（再解析用） |
| `data/index.json` | パッチ一覧（画面①） |
| `data/patches/<id>.json` | パッチ1件分の全変更点（画面①のタブ・画面②） |
| `data/entities.json` | キラー・パークごとの調整履歴（キャラ別・検索） |
| `data/dict/killers.json` | キラー名の辞書（手で管理。新キラーが出たら追加する） |

`<id>` はバージョン。PTB は `ptb-10.2.0` のように前に `ptb-` が付く。

## data/index.json

```jsonc
{
  "updatedAt": "2026-10-14T15:01:01.000Z",   // 最新パッチの投稿時刻
  "patches": [
    {
      "id": "10.2.0",
      "version": "10.2.0",
      "kind": "release",          // "release" | "ptb"
      "title": "10.2.0 | パッチノート",
      "date": "2026-10-06",
      "url": "https://store.steampowered.com/news/app/381210/view/...",
      "counts": { "buff": 32, "nerf": 2, "change": 15, "new": 1, "fix": 63 }
    }
  ]
}
```

新しい順に並ぶ。

## data/patches/&lt;id&gt;.json

```jsonc
{
  "id": "10.2.0", "version": "10.2.0", "kind": "release", "title": "...", "date": "2026-10-06", "url": "...",
  "changes": [
    {
      "entity": "憎悪の囁き",
      "cat": "perk",              // "killer" | "survivor" | "perk" | "system"
      "role": "killer",           // perk のときだけ: "killer" | "survivor"（不明なら無し）
      "character": "ナース",       // killer のときだけ: 辞書で特定できたキラー名（アドオン・能力の小見出しも本人に紐付け）
      "section": "殺人鬼パークのアップデート",
      "type": "buff",             // "buff" | "nerf" | "change" | "new"（新キャラ・新パークの追加）
      "diffs": [
        {
          "text": "発電機の修理が完了する度、修理完了した発電機の20メートル以内にいる生存者が10秒間表示される",
          "after": "20メートル以内 / 10秒間",   // 太字部分。無いときは null
          "before": "16メートル、5秒",          // （変更前：…）の中身。無いときは null
          "isNew": false,                       // （新効果）
          "type": "buff"                        // この行だけの判定。判定できないときは "change"
        }
      ],
      "lines": ["…パークの説明全文（変更のない行も含む）…"],
      "devNote": "開発チームより：…"            // あれば
    }
  ],
  "fixes": [ { "group": "オーディオ", "items": ["…を修正しました。"] } ]
}
```

## data/entities.json

キャラ別・検索で使う。対象はキラー（辞書にある名前）とパークだけ。サバイバーはキャラ個別の調整がなく、アイテムやクラスの話になるため入れていない。

```jsonc
{
  "憎悪の囁き": {
    "cat": "perk", "role": "killer",
    "history": [                // 新しい順。PTB は含めない
      { "id": "10.2.0", "version": "10.2.0", "date": "2026-10-06", "type": "buff", "diffs": [ ... ] },
      { "id": "9.6.0", "version": "9.6.0", "date": "...", "type": "nerf", "part": "ナースのアドオン", "diffs": [ ... ] }  // part = 本人以外の見出し
    ],
    "current": ["…最後に調整されたときの説明全文…"]
  }
}
```

## 強化・弱体化の判定（パターンA）

1行の中で `（変更前：…）` ごとに区切り、区切りごとに判定する。

1. `（新効果）` → 強化、`（削除）` → 弱体化。古い書式の `（以前はX）` `6%→10%` `16メートルから14メートルに` も読む
2. 変更前と変更後の数値を比べて、増えたか減ったかを出す（`6/12/18%` のような段階表記は平均で比べる）
3. 文に「クールダウン」「疲労」「必要」などがあれば「小さいほど良い」として向きを逆にする。
   ただし「25%短くなる」「10%増加する」のように数値が効果量を表す文は、大きいほど良い
4. 数値で比べられないとき → 変更

1つのキャラ・パークの中で全部が強化なら「強化」、全部が弱体化なら「弱体化」、混ざっていれば「変更」。
あくまで機械的な判定なので、誤判定はありうる。判定ルールは `scripts/extract.test.mjs` に実際の文で書いてあるので、誤判定を見つけたらそこにケースを足してから直す。

「新しい殺人鬼パーク」のような紹介セクションは「追加（new）」。「問題の修正」見出しの下と、「〜を修正しました」で終わる文は `fixes` に入る。
